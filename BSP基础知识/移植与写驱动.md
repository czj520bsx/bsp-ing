# 面试问答：板级 OOT 移植 vs 从零写外设驱动

> 结合本仓库 RK3562（SMIOS）显示/音频外挂实践整理。  
> 用途：面试口述提纲，按框架答，勿死记原文。

---

## 一、两条线怎么区分（开场必会）

| | 线 A：SoC 板级 / OOT 移植（本仓库） | 线 B：从零写外设驱动（如网卡/8025 类） |
|--|--|--|
| 对象 | 整棵子系统：DRM / ALSA + DT + ABI | 一颗外设：寄存器、probe、中断、业务接口 |
| 典型工作 | 裁核缺口、OOT 装载、板级拓扑、与现网镜像共存 | 读手册、套框架、收发/控制通路 |
| 难点 | 不能刷核、符号/ABI、MFD、通路/时钟/GPIO | 时序、协议、DMA、稳定性 |
| 产出 | DTB + kos 包 + 上板脚本 | 一个 `.ko` / 进树驱动 |
| 一句话 | 把公版子系统接到受限量产核上 | 把一颗芯片接入内核框架 |

**交叉题标准答：**  
写驱动是「芯片 → 框架」；移植是「子系统 → 这块板 / 这个现网 Image」。

## 二、线 A：板级 OOT 移植（DRM / 音频）

### A1. 你做了什么？（1 分钟开场）

**可能问法**
- 介绍一下显示/音频你具体交付了什么？
- 为什么不直接刷公版内核？

**答要点**
- 现网验签 Image：`5.10.198`，`# CONFIG_DRM is not set` / `# CONFIG_SOUND is not set`，不能刷核/U-Boot。
- 方案：**可换 DTB + OOT `.ko`**，对齐 vermagic/ABI 198。
- 交付：
  - 显示：`kx/移植/drm/drm-kos-198` + `insmod.sh`，LVDS + Qt
  - 音频：`kx/移植/snd/snd-kos-198` + `insmod.sh` / `play.sh`，RK809 喇叭
  - 公共：`switch-kernel-abi.sh`、`abi-headers/`、板级 DT（`kx/移植/rockchip/`）

**金句**  
不是重写 VOP/SAI，是在「不能换核」约束下把子系统接到量产板上。

---

### A2. 链路怎么样？

#### 显示

**可能问法**
- 一帧图从 Qt 到屏怎么走？
- DRM 里 Plane / CRTC / Encoder / Connector 是什么？

**通路**

```text
用户态 Qt（linuxfb + FB_DRM / DRM dumb）
  → /dev/dri/card0
  → DRM/KMS（drm.ko + rockchipdrm.ko）
  → VOP2（CRTC/Plane）
  → LVDS encoder
  → panel-simple
  → 物理屏
附：video_phy 依赖 phy_mipi_dphy + phy-rockchip-inno-dsidphy
```

**对象口诀**  
Plane 贴 FB → CRTC 扫 → Encoder 编码 → Connector 到屏。

#### 音频

**可能问法**
- 播 MP3 的内核路径？
- ASoC 三层是什么？芯片是 RK817 还是 RK809？

**通路**

```text
mpg123 / aplay
  → ALSA PCM（/dev/snd/pcmC0D0p）
  → Machine：rockchip-multicodecs
  → CPU DAI：SAI0  ↔  Codec：RK809（驱动 snd-soc-rk817）
  → HPL/HPR + GPIO PA_CTL（外置功放）
  → 喇叭
```

**ASoC 三层**  
Machine（板级绑定） / CPU DAI（SAI） / Codec（RK809）。

**809 vs 817**  
硬件是 **RK809**；codec 驱动与 RK817 共用（`compatible` 含 `rk817-codec`，模块名 `snd-soc-rk817`）。

### A3. 排查了什么？（案例表，最加分）

**可能问法**
- 过程中卡过哪些点？怎么定位的？
- 有设备但没声/没图怎么查？

| 现象 | 根因 | 处理 |
|------|------|------|
| 无 `/dev/dri`、无 `/proc/asound` | Image 未开 DRM/SOUND | 整栈 `CONFIG_*=m` OOT 外挂 |
| modpost `exported twice` | `Module.symvers` 误含 vmlinux 假导出 | 从 `Module.symvers.nodrm` 剥离冲突符号 |
| `dma_buf_cache_*` Unknown symbol | 编时开了 `DMABUF_CACHE`（Rockchip 默认 y），现核没有 | fragment 强制 `# CONFIG_DMABUF_CACHE is not set` 重编 |
| DT 有 `pmic@20/codec` 仍无 codec 设备 | 现网 `rk808` MFD 无 `rk817-codec` cell | `rk809_codec_bridge.ko` 挂到 I2C `0-0020` |
| PCM 跑完喇叭无声 | 外置功放需 `Playback Path=SPK_HP` | `insmod`/`play` 里设置 |
| `amixer`/`aplay` close 时 `put_pid` oops | 现网 `task_pid` ABI 与 SDK 头不一致 | `sound/core/control.c`、`pcm.c` 跳过 pid（同 DRM `drm_file`） |
| `Invalid CTL hw:0` | 侧载工具缺 `alsa.conf` | `ALSA_CONFIG_PATH` + `ld-linux` 跑 BR 工具，勿乱 `LD_LIBRARY_PATH` |
| vermagic 拒绝 | 用了 226 头/SUBLEVEL 编的 ko | `switch-kernel-abi.sh 198` 后重编 |

**定位口诀**  
先分清：**没设备** / **有设备没通路** / **用户态环境坏了**。

---

### A4. 思路怎么样？（方法论）

**可能问法**
- 不能刷核时你怎么下手？
- ko 加载顺序怎么定？
- 198/226 ABI 切换是干什么的？

**下手步骤**
1. 板上诊断：`config.gz`、`/dev/dri`、`/proc/asound`、运行中 DT  
2. 对照公版：缺哪些子系统、DT 拓扑长什么样  
3. `=m` 编出 ko；用 `modules.order` / `modinfo depends` / 试装报错定顺序  
4. 先换 DTB 并重启（MFD 子设备多在启动时创建）  
5. `insmod`；`Unknown symbol` → 查谁 export → 补模块或改 CONFIG  
6. 最后收口通路与用户态（Path、alsa.conf、Qt）

**装载顺序原则**  
时钟/deps → 框架 core → 平台/PHY → 设备驱动 → **Machine/汇总驱动最后**。

**ABI 切换**  
SDK 树偏 226，现网 198；`switch-kernel-abi.sh` 安装 `abi-headers/{198,226}` 并改 `SUBLEVEL`，保证能 `insmod`。drm/snd 共用。

### A6. 30 秒口述卡（线 A）

> 量产核裁了 DRM/ALSA，验签不能刷 Image。我恢复板级 DT 拓扑，把显示和音频做成对齐 5.10.198 的 OOT 模块包。显示打通 VOP2+LVDS+Qt；音频走 SAI0+RK809，并用 bridge 补上 MFD 未创建的 codec 设备；外置功放用 `SPK_HP` 通路。过程中处理过 ABI、假 Module.symvers、`DMABUF_CACHE`、以及用户态 alsa 配置等问题。

## 三、线 B：从零写外设驱动（网卡/8025 类模板）

> 按你真实芯片名替换「8025/XX」。结构可直接套。

### B1. 你做了什么？

**可能问法**
- 这个驱动你负责到哪一层？
- 用的什么总线？实现了哪些接口？

**答结构**
- 芯片角色（MAC/PHY/WiFi/…）与总线（PCI/USB/SDIO/SPI/…）  
- 接入框架（如 `net_device_ops` / `platform_driver`）  
- 完成能力：probe、开关网、收发、基础 ethtool/统计  
- 验证：iperf、收发包、长时间挂机  

---

### B2. 链路怎么样？

**网卡示例**

```text
应用 socket
  → 协议栈
  → ndo_start_xmit / NAPI poll
  → 驱动：描述符环 + DMA + 寄存器
  → MAC/PHY
  → 物理链路
```

**常追问**
- `probe` 里做哪些事？（资源、ioremap、dma、注册 netdev、请求中断）  
- 中断还是 NAPI？为什么？  
- 一次发包从 `ndo_start_xmit` 到踢硬件 doorbell 的步骤？  

---

### B3. 排查了什么？

| 现象 | 常见方向 |
|------|----------|
| probe 失败 | 时钟/复位/供电/DT compatible/BAR 映射 |
| 能识别不上网 | PHY link、MAC 地址、接口 up、checksum |
| 偶发丢包/卡住 | 环缓冲、NAPI、cache 一致性、关中断时机 |
| 休眠唤醒异常 | runtime PM、resume 是否重初始化 |

用「现象 → 证据（log/寄存器/统计）→ 修改」讲一个完整故事即可。

---

### B4. 思路怎么样？

1. 读手册：复位时序、关键寄存器、中断原因、DMA  
2. 套框架：最小 `probe` + 注册设备  
3. 先打通最小收发，再开 offload/多队列  
4. 用 ethtool、tcpdump、驱动统计定位  

---

### B5. 30 秒口述卡（线 B 模板）

## 四、对比与综合题

**Q：移植和写驱动本质区别？**  
写驱动以硬件手册 + 框架回调为主；移植以子系统拓扑、依赖、DT、与现网镜像共存为主。

**Q：你更擅长哪个？**  
按实情：近期深度在板级 bring-up；单芯片驱动有 XX；两者互补。

**Q：遇到 `Unknown symbol` 怎么查？**  
`modinfo depends` → `nm` / `Module.symvers` 找导出方 → 调整 `insmod` 顺序或补模块/关错误 CONFIG。

**Q：怎么证明不是只会跑脚本？**  
能画链路；能讲 2 个坑的因果；能回答「如果没有 bridge / 如果打开 DMABUF_CACHE 会怎样」。
