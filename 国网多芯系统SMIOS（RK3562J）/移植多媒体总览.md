# OOT 三路移植从零说明（显示 / 音频 / 摄像头）

面向现网验签 Image `5.10.198`（`#236`）：**不换核**，用 **DTB + 外挂 `.ko` + 少量用户态** 打通三条链路。

路径根：`kx/移植/`。编 OOT 前：

```bash
./kx/移植/switch-kernel-abi.sh 198 --with-config
```

---

## 一、三条完整链路

### 1. 屏幕（DRM）

```
用户态 Qt（平台插件名仍叫 `linuxfb`，但 **`QT_QPA_FB_DRM=1` → 走 DRM KMS dumb**）
        ↓  /dev/dri/card0   （本板 **没有** `/dev/fb*`：刻意 skip fbdev_init）
rockchipdrm.ko  (VOP2 + LVDS encoder + panel bridge)
        ↓
VOP2 (vp0) → route_lvds → LVDS 控制器 → video_phy → panel-lvds (GV101 1280×800)
```

辅助模块：`drm_deps` / `cfb_*` / `sys_*` / `fb_sys_fops` / `fb_defio` / `drm` / `drm_kms_helper` / `panel-simple` /（可选）`phy_mipi_dphy` + `phy-rockchip-inno-dsidphy`。

说明：内核侧 **不做** DRM fbdev 仿真 → 无 `/dev/fb0`；Qt 里的 `linuxfb` 只是插件名，加 `QT_QPA_FB_DRM=1` 后画到 **`/dev/dri`**，不是传统 framebuffer 设备。也可改用 `eglfs`（`run_qt_eglfs.sh`）。

### 2. 声卡（ALSA / ASoC）

```
aplay/mpg123 (tools/run.sh)
        ↓  ALSA PCM
multicodecs 卡 "rockchip-rk809"
        ↓
SAI0 (I2S)  ↔  RK809 codec (snd-soc-rk817)
        ↓
HPL/HPR + GPIO3_C6 PA_CTL（外置功放，Playback Path=SPK_HP）
```

现网 `rk808` MFD 在 `SOUND=n` 时往往 **没有** `rk817-codec` cell，所以要自研 `rk809_codec_bridge.ko` 补 platform 设备。

### 3. 摄像头（V4L2 + rkaiq）

```
rkaiq_3A_server  ←→  params/stats 节点
        ↓
GC05A2 @ i2c5 0x37
  → csi2-dphy0 → mipi0-csi2 → rkcif_mipi_lvds
  → rkcif_mipi_lvds_sditf → rkisp_vir0 → rkisp_mainpath (/dev/video11 一类)
        ↓
NV12 抓帧 (grab_3a.sh + v4l2_grab)
```

你的理解正确：**sensor + dphy + cif + isp**（再加 MIPI-CSI2 与虚 ISP 节点）。现网 `# CONFIG_MEDIA_SUPPORT is not set`，整套 media 栈都要 OOT。

## 二、设备树怎么拆

板级入口：

```1:23:kx/移植/rockchip/kx_rk3562-core-ddr4-v10.dts
// ...
#include "rk3562j.dtsi"
#include "rk3562-rk809.dtsi"
#include "kx_rk3562-display.dtsi"
#include "kx_rk3562-camera.dtsi"
#include "kx_rk3562-audio.dtsi"
```

| 文件 | 职责 |
|------|------|
| `kx_rk3562-display.dtsi` | 补回多核裁掉的 VOP/LVDS/`display_subsystem`/`route_*`（默认 disabled） |
| `kx_rk3562-audio.dtsi` | 补回 `sai0`、`mclkout_sai0`、`rk809-sound` |
| `kx_rk3562-camera.dtsi` | 补回 dphy / mipi-csi2 / rkcif / rkisp 等 SoC 节点 |
| `kx_rk3562-core-ddr4-v10.dts` | 板级：panel、使能哪个接口、sensor、功放脚等 |

### 显示（板级使能）

```612:663:kx/移植/rockchip/kx_rk3562-core-ddr4-v10.dts
&display_subsystem {
	status = "okay";
};
// ...
&route_lvds {
	connect = <&vp0_out_lvds>;
	status = "okay";
};
&lvds {
	status = "okay";
	ports {
		port@1 {
			reg = <1>;
			lvds_out_panel: endpoint {
				remote-endpoint = <&panel_in_lvds>;
			};
		};
	};
};
&vop {
	status = "okay";
};
```

面板节点（同文件 `panel-lvds`）：`simple-panel` + 1280×800 timing + `remote-endpoint = <&lvds_out_panel>`。

### 音频（板级使能）

SoC 侧在 `kx_rk3562-audio.dtsi`：

```text
sai0 @ ff800000          → rockchip,sai
rk809_sound              → rockchip,multicodecs-card (cpu=&sai0, codec=&rk809_codec)
mclkout_sai0             → rockchip,clk-out
```

板级：
 
```920:942:kx/移植/rockchip/kx_rk3562-core-ddr4-v10.dts
&sai0 {
	status = "okay";
	// pinctrl i2s0m0_*
};
&rk809_sound {
	status = "okay";
	// ...
};
&rk809_codec {
	use-ext-amplifier;
	spk-ctl-gpios = <&gpio3 RK_PC6 GPIO_ACTIVE_HIGH>;
};
```

`rk809_codec` 本体在 `rk3562-rk809.dtsi`（PMIC 子节点）。

### 摄像头（板级拓扑）

```text
i2c5 / gc05a2@37 → endpoint → csi2-dphy0 → mipi0-csi2
  → rkcif_mipi_lvds → rkcif_mipi_lvds_sditf → rkisp_vir0
```

工作路径建议用 **sensor 自管 xvclk/reset/pwdn**（smios 树里方案1）；`cam-kos` 的 `insmod.sh` 会卸掉 `cam_mclk`。板级关键使能：`&i2c5`、`&gc05a2`、`&csi2_dphy0`、`&mipi0_csi2`、`&rkcif`、`&rkisp`、`&rkisp_vir0` 等为 `okay`；`rkcif_mmu` / `rkisp_mmu` 本板常 `disabled`（无可用 IOMMU domain）。

编 DTB：

```bash
bash ./kx/移植/rockchip/build_kx_kernel_dtb.sh
```

## 三、怎么确定 `insmod` 顺序

**没有神秘模板**，原则就三条：

1. **被依赖的先装**（谁 `EXPORT_SYMBOL`，谁先 `insmod`）
2. **看串口 `Unknown symbol xxx`**，缺谁补谁，再调整顺序
3. **总线/卡创建顺序**：例如 bridge 必须在 `snd-soc-rk817` 之前；media 先 `media_deps` 再 vb2 再 cif/isp，sensor 最后

对照现成脚本：

| 子系统 | 脚本 |
|--------|------|
| 显示 | `drm/drm-kos-198/insmod.sh` |
| 音频 | `snd/snd-kos-198/insmod.sh` |
| 相机 | `cam/cam-kos-198/insmod.sh` |

显示顺序（摘要）：

```sh
insmod drm_deps.ko          # 补 hdmi/videomode/fence 等
insmod cfbfillrect.ko ...   # FB helpers，给 drm_kms_helper
insmod fb_defio.ko
insmod drm.ko
insmod drm_kms_helper.ko
insmod panel-simple.ko
insmod rockchipdrm.ko       # 最后：绑 VOP/LVDS
```

音频顺序（摘要）：

```sh
clk-out → soundcore → snd → timer/pcm → snd-soc-core
→ snd-soc-rockchip → sai
→ rk809_codec_bridge → snd-soc-rk817 → multicodecs
```

相机顺序（摘要）：

```sh
media_deps → mc → videodev → vb2_* → csi2-dphy* → video_rkcif → video_rkisp → gc05a2
```

排障口诀：一次装一个；盯 `Unknown symbol` / `Invalid module format` / `Oops` 的 `pc`/`Comm:`/`Modules linked in`。案例集：`drm/OOT-KO-OOPS-CASES.md`。

## 四、拷贝整树后怎么单独编译

### 4.1 自研小模块（最简单）

目录里放 `Makefile`，用内核的 `M=`：

```makefile
# 例：kx/移植/snd/rk809-codec-bridge/Makefile
KDIR ?= .../kernel-5.10
ARCH ?= arm64
CROSS_COMPILE ?= aarch64-linux-gnu-

obj-m += rk809_codec_bridge.o

all:
	$(MAKE) -C $(KDIR) M=$(CURDIR) ARCH=$(ARCH) CROSS_COMPILE=$(CROSS_COMPILE) modules
```

```bash
./kx/移植/switch-kernel-abi.sh 198 --with-config
cd kx/移植/snd/rk809-codec-bridge && make
```

`drm-deps`、`media-deps`、`fb-defio` 同理（`obj-m` + 多 `.o` 链成一个 ko）。

### 4.2 拷贝的整棵驱动树（drm / sound / video_rkisp）

不改内核树路径时，**绝对路径 `M=`** 指向副本即可：

```bash
# 概念：与 build_drm_kos.sh / build_snd_kos.sh 相同
cd "$KERN"   # kernel-5.10
make modules_prepare
make -j$(nproc) M=/绝对路径/kx/移植/drm/drm modules KBUILD_MODPOST_WARN=1
make -j$(nproc) M=/绝对路径/kx/移植/snd/sound modules KBUILD_MODPOST_WARN=1
```

要点：

1. **ABI=198**（`switch-kernel-abi.sh`）
2. `.config` 里目标子系统为 `=m`（用 `*-fragment.config` merge）
3. 清洗 `Module.symvers`：`Module.symvers.nodrm` 里常有「假 vmlinux 导出」，不剥会 `exported twice`
4. 缺符号用 `KBUILD_MODPOST_WARN=1`，运行时再靠先装的 shim/helper ko 满足
5. 把需要的 `.ko` `cp` 进 `*-kos-198/`

现成脚本（照抄即可）：

- `kx/移植/drm/build_drm_kos.sh` → `M=$DRM_DIR/drm`
- `kx/移植/snd/build_snd_kos.sh` → `M=$SND_DIR/sound`
- `kx/移植/cam/build_cam_kos.sh` → `M=` 各 cam 子目录 + canary 1192

## 五、什么时候改代码、怎么根据报错改（含本仓例子）

### 判断流程

```
装不上 / probe 失败 / Oops / 功能不对
        │
        ├─ vermagic 不对 → 切 198 重编（改编译环境，不改业务代码）
        ├─ Unknown symbol xxx
        │     ├─ 符号本应在别的 ko → 调整 insmod 顺序 / 把该 ko 编进包
        │     └─ 现核永远不会导出 → 自研 shim EXPORT，或拷一份源码编模块
        ├─ Oops 在 put_pid / task_struct / canary → ABI：改头或绕开 API
        ├─ Oops 在 fbcon / 错误路径 cleanup → 跳过子系统或加空指针防护
        └─ 功能层（无 IOMMU、CMA、MFD 缺 cell）→ 改驱动策略或 bridge
```

### 例子 A：缺导出 → 自研 shim ko

**现象：** `Unknown symbol dma_fence_signal_timestamp` / `cma_alloc` / `memblock_free` …

**改法：** 不改 Image，写模块把符号补出来。

`drm_deps` — fence：

```c
/* kx/移植/drm/drm-deps/dma_fence_shim.c */
int dma_fence_signal_timestamp(struct dma_fence *fence, ktime_t timestamp)
{
	unsigned long flags;
	int ret;
	if (!fence)
		return -EINVAL;
	spin_lock_irqsave(fence->lock, flags);
	ret = shim_dma_fence_signal_timestamp_locked(fence, timestamp);
	spin_unlock_irqrestore(fence->lock, flags);
	return ret;
}
EXPORT_SYMBOL(dma_fence_signal_timestamp);
```

`drm_deps` — 空操作导出：

```c
/* kx/移植/drm/drm-deps/kernel_export_shim.c */
int memblock_free(phys_addr_t base, phys_addr_t size)
{
	return 0;
}
EXPORT_SYMBOL_GPL(memblock_free);

int sched_setscheduler(struct task_struct *p, int policy,
		       const struct sched_param *param)
{
	return 0;
}
EXPORT_SYMBOL_GPL(sched_setscheduler);
```

`media_deps` — 真 CMA（板核有 DMA-CMA，但 `cma_alloc` 未导出给模块）：

```c
/* kx/移植/cam/media-deps/cma_shim.c（核心逻辑） */
struct page *cma_alloc(struct cma *cma, size_t count, unsigned int align,
		       gfp_t gfp_mask)
{
	struct page *page;
	(void)cma;
	(void)gfp_mask;
	page = try_dma_cma(count, align);   /* → dma_alloc_from_contiguous() */
	if (page)
		return page;
	page = try_contig(count);
	if (page)
		return page;
	return try_buddy(count, gfp_mask);  /* 仅小块兜底；8MiB NV12 不够 */
}
EXPORT_SYMBOL_GPL(cma_alloc);
```

### 例子 B：MFD 缺 cell → 自研 bridge

**现象：** DTB 有 codec 节点，但没有 `rk817-codec` 设备，`snd-soc-rk817` 不 probe。

```c
/* kx/移植/snd/rk809-codec-bridge/rk809_codec_bridge.c */
codec_np = of_find_compatible_node(NULL, NULL, "rockchip,rk817-codec");
/* ... 找到 RK809 i2c client ... */
pdev = platform_device_alloc("rk817-codec", PLATFORM_DEVID_NONE);
pdev->dev.parent = &client->dev;
pdev->dev.of_node = codec_np;
platform_device_add(pdev);
```

### 例子 C：ABI / `task_pid` → `put_pid` Oops

**现象：** `modetest`/`amixer`/`aplay` 退出时 Oops，`pc` 在 `put_pid`。

**改法：** 跳过 pid 跟踪（仅调试用）。

```c
/* drm/drm_file.c */
file->pid = NULL;   /* 原: get_pid(task_pid(current)) */
```

```c
/* sound/core/control.c */
ctl->pid = NULL;
```

```c
/* sound/core/pcm.c */
substream->pid = NULL;
```

### 例子 D：与内置 fbcon ABI 打架

**现象：** bind 后 `fbcon_startup` Oops。

**改法：** 跳过 DRM fbdev 仿真（Qt 走 KMS）。

```c
/* rockchip_drm_drv.c */
/* 原: rockchip_drm_fbdev_init() */
DRM_DEV_INFO(dev, "skip rockchip_drm_fbdev_init (OOT/fbcon ABI)\n");
```

### 例子 E：错误路径空指针

**现象：** writeback connector init 失败后 unbind Oops。

```c
/* rockchip_drm_vop2.c */
static void vop2_wb_connector_destory(struct vop2 *vop2)
{
	if (!vop2->wb.conn.encoder.dev)
		return;
	drm_encoder_cleanup(&vop2->wb.conn.encoder);
	drm_connector_cleanup(&vop2->wb.conn.base);
}
```

### 例子 F：无 IOMMU → ISP 策略

**现象：** DT 写了 iommus 但无 domain；开 BAY3D 等 DDR 模块会砸内存。

```c
/* video_rkisp/hw.c */
if (hw_dev->is_mmu && !iommu_get_domain_for_dev(dev)) {
	dev_info(dev, "OOT: DT iommu listed but no domain, non-iommu buffers\n");
	hw_dev->is_mmu = false;
}
```

```c
/* isp_params_v32.c */
static inline bool rkisp_oot_skip_iq_ddr(struct rkisp_device *dev)
{
	return !dev || !dev->hw_dev || !dev->hw_dev->is_mmu;
}
/* 无 MMU 时 skip BAY3D/LDCH/CAC/3DLUT；STREAMOFF 时 keep IQ CMA */
```

STREAMOFF 先停 3A 再停 params（避免 dma_fd UAF）：

```c
/* rkisp.c */
rkisp_stop_3a_run(isp_dev);
rkisp_params_stream_stop(&isp_dev->params_vdev);
```

### 例子 G：`card->owner` 为空

```c
/* rockchip_multicodecs.c */
card->owner = THIS_MODULE;
```

## 六、用户态：编的还是拷的？

| 子系统 | 组件 | 来源 |
|--------|------|------|
| **DRM** | `qt_smoke` + Qt/插件/字体/`ld-linux` | **编 + 打包**：`qt-drm-smoke/`；默认 `QT_QPA_PLATFORM=linuxfb` + **`QT_QPA_FB_DRM=1`**（画到 `/dev/dri`，**不是** `/dev/fb*`）；也可用 `eglfs` |
| **SND** | `aplay`/`amixer`/`mpg123` + `alsa.conf` | **侧载拷贝进** `snd-kos-198/tools/`（SMIOS 缺完整 alsa）；`tools/run.sh` 设 `ALSA_CONFIG_PATH` |
| **CAM** | `rkaiq` / `rkaiq_3A_server` / IQ | **编**：`build_rkaiq.sh` 用 Buildroot 工具链编 `camera_engine_rkaiq/` 副本 → `cam-kos-198/tools/rkaiq/` |
| **CAM** | `v4l2_grab`、`media_link_setup` | **自研小工具**（目录内 `.c` + Makefile） |
| **CAM** | IQ 默认路径 / 分辨率 | 改了 `rkaiq_3A_server.cpp`：`/tmp/iqfiles/`、`2592×1944` |

用户态关键环境变量示例：

```sh
# Qt
QT_QPA_PLATFORM=linuxfb
QT_QPA_FB_DRM=1

# ALSA（必须走 tools/run.sh）
ALSA_CONFIG_PATH=.../usr/share/alsa/alsa.conf
```
